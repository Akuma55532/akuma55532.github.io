## 什么是组播？

作为IP传输三种方式之一，组播指的是报文从一个源发出，被转发到一组特定的接收者，相同的报文在每条链路上最多有一份。相较于传统的单播和广播，组播可以有效地节约网络带宽、降低网络负载，所以被广泛应用于IPTV、实时数据传送和多媒体会议等网络业务中。

## 组播和单播的区别是什么？

组播和单播都是报文传输的一种方式。

单播是主机间一对一的通讯模式，网络中的设备根据网络报文中包含的目的地址选择传输路径，将单播报文传送到指定的目的地，只对接收到的数据进行转发，不会进行复制。它能够针对每台主机及时的响应，现在的网页浏览全部都是采用单播模式。

组播是主机间一对多的通讯模式， 组播是一种允许一个或多个组播源发送同一报文到多个接收者的技术。组播源将一份报文发送到特定的组播地址，组播地址不同于单播地址，它并不属于特定某个主机，而是属于一组主机。一个组播地址表示一个群组，需要接收组播报文的接收者都加入这个群组。

一份数据报文如图所示，通过单播传输需要使用一个单播地址作为目的地址。数据源向每个接收者发送一份独立的报文。如果网络中存在N个接收者，则数据源需要发送N份报文；通过组播传输时使用一个组播地址作为目的地址，数据源向组播组发送且仅发送一份报文。如果网络中存在N个接收者，数据源也仅需要发送一份数据报文。

![image1.png](https://cloudflare-imgbed.wx3515753265.workers.dev/file/blog/组播通信/1788960122756_image1.png)

组播传输和单播传输方式对比
单播传输适用于用户稀少的网络，如果用户量较大时，网络将会出现多份相同的流量，会大量占用处理器资源而且非常浪费网络的带宽，而通过组播方式传输，网络中每条链路中仅有一条数据流。组播相比于单播的优势在于相同的报文在每条链路上最多有一份。

## 组播和广播的区别是什么？

组播和广播都是报文传输的一种方式。

广播是主机间一对所有的通讯模式，设备会将报文发送到网络中的所有可能接收者。设备简单地将它收到的任何广播报文都复制并转发到除该报文到达的接口外的每个接口。广播处理流程简单，不用选择路径。

组播是主机间一对多的通讯模式， 组播是一种允许一个或多个组播源发送同一报文到多个接收者的技术。

一份数据报文如图所示，通过广播传输需要使用一个广播地址作为目的地址。数据源向本网段对应的广播地址发送且仅发送一份报文。广播传输会把数据报文发送给本网段中的所有用户，而不管用户是否有需求；通过组播传输时仅把数据报文发送给有数据需求的用户，不会发送给所有用户。

![image2.png](https://cloudflare-imgbed.wx3515753265.workers.dev/file/blog/组播通信/1788960121316_image2.png)

组播传输和广播传输方式对比
广播传输数据源必须与用户在同一个网段，组播可以跨网段传输。广播传输该网段内所有主机都能收到数据报文，会导致无信息需求的主机也收到该信息，网络中存在流量冗余，组播传输只将数据流传输到有接收者的地方，网络中不存在流量冗余。组播相比于广播的优势在于组播的报文是按需发送。

## 组播的MAC地址

为了在本地物理网络上实现组播信息的正确传输，需要在链路层使用组播MAC地址。组播数据传输时，其目的地不是一个具体的接收者，而是一个成员不确定的组，所以需要一种技术将IP组播地址映射为组播MAC地址。

## 最后回到我今晚遇到的问题

### 组播的MAC地址和网卡设备的MAC地址

首先我们要知道组播的mac地址和设备的网卡mac地址有很大区别的。

组播的mac地址是由组播的IP地址根据固定关系映射过来的，就像是一个微信群的微信群号，因此这个组播mac地址是可变的（随着组播IP变动）。

而设备的网卡mac是直接在出场的时候被固化在网卡硬件里面了。

### 白名单

MAC地址白名单是网络访问控制的一种核心机制。它基于设备的物理地址（MAC地址）来进行身份验证，其核心逻辑是：**仅允许预先录入在“白名单”列表中的设备接入网络，拒绝所有未登记的设备。**

#### 工作原理与模式对比

MAC地址过滤通常在数据链路层（如802.11协议的关联阶段）生效，主要分为两种互斥的模式：
- **白名单模式（允许列表）**：采取“非白即黑”的严格策略。只有匹配白名单列表的用户才能接入网络，其他所有用户均被拒绝。这种模式安全性最高，但管理成本也最大。
- **黑名单模式（禁止列表）**：采取“非黑即白”的宽松策略。仅阻止黑名单中的特定设备接入，其余设备均可自由连接。适用于临时管控或屏蔽已知恶意设备。

#### 白名单机制的使用

MAC白名单机制并非只存在于单一位置，而是根据设备所处的网络层级，呈现出多层级的防御体系。通常我们可以将其划分为以下四个核心层级：
1. 硬件底层（网卡芯片/链路层）
这是最靠近物理网络的“第一道大门”。
机制：在网卡（NIC）或蓝牙（BLE）等通信芯片内部，存在硬件级的过滤器（如链路层过滤器 Link Layer Filter）。
作用：它直接在硬件电路上进行比对，不匹配白名单的数据包在物理接收阶段就会被直接丢弃，甚至不需要唤醒CPU。这种方式效率极高、延迟极低，是防止非法探测和无效数据涌入的最底层防线。
2. 操作系统层（Linux内核防火墙）
这是运行在主机系统内部的“第二道关卡”。
机制：当数据通过了硬件层进入操作系统后，Linux内核的防火墙工具（如 iptables 或 nftables）会在数据链路层对流量进行二次校验。
作用：系统会根据预设的 FORWARD 或 INPUT 规则，匹配源MAC地址。只有命中白名单规则的流量才会被放行，其余一律拦截。这层过滤适合对进入本机的特定接口流量进行轻量级的精准控制。
3. 网络接入设备层（路由器/交换机）
这是控制局域网准入的“第三道关卡”。
机制：在网络接入点，路由器或交换机通过配置MAC地址过滤（黑白名单）或端口安全（Port Security）功能，对试图接入网络的设备进行识别。
作用：接入设备会自动比对请求连接的MAC地址。符合白名单的设备正常获取IP并访问网络，未登记的非法设备则会被拒绝连接或丢弃数据包。这层机制常用于家庭防蹭网或企业办公网的准入控制。
4. 企业级边界层（硬防火墙）
这是部署在内外网交界处的“最高级安全屏障”。
机制：企业级硬防火墙采用专用芯片（如ASIC/NPU）进行多核并行处理，能够基于OSI模型进行2到7层的逐层深度检测。
作用：在数据链路层（L2），硬防火墙同样会执行基于源/目的MAC地址的黑白名单过滤机制，防止跨VLAN的非法通信或MAC洪泛攻击。结合其强大的硬件加速能力，它能在高并发场景下实现微秒级的低延迟过滤。

---

总结来说，白名单机制是一个从底层硬件芯片、操作系统内核，一直延伸到网络接入设备和企业级防火墙的立体防护体系。层级越靠下（如硬件层），过滤的效率越高；层级越靠上（如防火墙层），管控的范围和策略越复杂。
在排查通信问题的时候，应该按照顺序逐层排查。

## 排查组播

那么通常我们难以排查的地方就是网卡的mac白名单里面如果没有我们的组播mac地址，那么他就会自动过滤掉所有的组播消息，这就会导致明明软件配置没问题，但就是接收不到信息。

### 网卡硬件组播过滤

现象：tcpdump 能看到帧，recv 却收不到；但一开 tcpdump（混杂）就能收。

原因：网卡只按“硬件组播过滤表”收帧，驱动没把目标组 MAC
（`224.0.0.255` → `01:00:5e:00:00:ff`）写进过滤表 → 帧在网卡硬件层就被丢，
根本到不了内核 socket（软件层 `IP_ADD_MEMBERSHIP` 一切正常）。

验证/解决：
```bash
# 方法A：让网卡收所有组播（本次修复）
sudo ip link set eth1 allmulticast on
# 方法B：混杂模式（等价 tcpdump 效果）
sudo ip link set eth1 promisc on
# 确认网卡已带 MULTICAST,ALLMULTI
ip link show eth1
```

> 关键判据：`allmulticast on` / 混杂模式一开，recv 就能收得到组播消息 → 即此根因。

#### 持久化（重启不失效）——NetworkManager dispatcher
```bash
sudo tee /etc/NetworkManager/dispatcher.d/50-eth1-allmulti > /dev/null <<'EOF'
#!/bin/bash
if [ "$1" = "eth1" ] && [ "$2" = "up" ]; then
    ip link set eth1 allmulticast on
fi
EOF
sudo chmod 755 /etc/NetworkManager/dispatcher.d/50-eth1-allmulti
# 验证：
sudo nmcli con up "Wired connection 2"   # 用你实际连接名
ip link show eth1                        # 应看到 ALLMULTI
```
